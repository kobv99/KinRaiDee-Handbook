# Request for Comments Process

An RFC is required before implementing a large feature or architectural change whose scope, risks, or alternatives need team agreement.

## RFC lifecycle

```text
Draft
  -> Discussion
  -> Revision
  -> Accepted or Rejected
  -> Implementation
  -> Outcome review
```

## RFC topics

Typical RFC candidates include:

- Shopping Engine;
- Nutrition data source and calculations;
- Meal planning;
- AI model runtime and distribution;
- barcode, OCR, or vision input;
- cloud sync;
- family sharing;
- authentication;
- paid features or subscriptions;
- breaking migrations.

## Minimum RFC contents

- user problem;
- goals and non-goals;
- proposed workflow;
- data model impact;
- architecture impact;
- offline behaviour;
- privacy and safety impact;
- alternatives;
- acceptance criteria;
- rollout and migration plan;
- open questions.
