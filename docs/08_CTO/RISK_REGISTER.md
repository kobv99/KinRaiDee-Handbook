# KinRaiDee Architecture Risk Register

- Audit date: 2026-07-26
- Application commit: `d8631869bb7e0eb18a9cc136189006212f8737dd`
- Status vocabulary: Open, Mitigating, Accepted, Closed

| Risk | Probability | Impact | Mitigation | Owner | Trigger | Status |
|---|---|---|---|---|---|---|
| **R-01 Pantry/History divergence after partial write.** Pantry is saved before History in `PantryNotifier.applyQuantityTransaction` (`apps/mobile/lib/core/providers/pantry_provider.dart:248-253`) and in `CookingHistoryPage._applyAdjustment` (`cooking_history_page.dart:89-99`). | High | Critical: inventory and audit history disagree; retry may deduct twice. | Introduce one idempotent application transaction with atomic storage or durable journal/compensation; add second-write-failure and restart tests. | Principal Engineer | Any storage exception or process termination between Pantry and History writes. | Open |
| **R-02 Stale transaction overwrites newer Pantry data.** `applyQuantityTransaction` assigns `afterQuantity` without checking current `beforeQuantity`, unit, missing IDs, or duplicates (`pantry_provider.dart:228-246`). | Medium | Critical: user edits can be silently lost and History can record changes that did not apply. | Validate all preconditions as one set before mutation; reject the whole transaction on any mismatch; persist a revision or `updatedAt`. | Pantry Domain Owner | A planned cooking/Shopping transaction is applied after a Pantry edit, delete, or unit change. | Open |
| **R-03 Quick undo partially restores a multi-lot transaction.** `undoQuantityTransaction` persists any restorable lot but cancels History only when all restore (`pantry_provider.dart:260-301`); existing tests are single-item (`pantry_provider_test.dart:85-203`). | Medium | High: Pantry partially rolls back while History remains completed. | Define all-or-nothing undo or an explicit partial outcome; add multi-lot changed/deleted-item tests. | Pantry Domain Owner | One of several deducted lots changes before the user taps undo. | Open |
| **R-04 Shopping duplicates or shortages are wrong because identity is name-based.** Pantry `Ingredient` lacks a canonical ID (`core/models/ingredient.dart:1-42`), `FoodItem` lacks IDs (`food_category.dart:13-38`), and matching uses aliases (`ingredient_name_matcher.dart:3-56`). | High | Critical: wrong items are merged, omitted, or over-purchased. | Approve shared taxonomy, lot IDs, variant/parent rules, custom-item policy, and migration before Shopping models are implemented. | CTO + Product + Data Owner | Recipe shortage generation or Shopping duplicate merge is implemented using display names. | Open |
| **R-05 Unit aggregation combines incompatible quantities.** Pantry, Recipe, transaction, and History units are strings; conversions are bounded in `recipe_serving_calculator.dart`. | High | High: incorrect quantities, deductions, and purchase amounts. | Approve canonical dimensions/units, precision, aliases, and rejection behavior; add cross-feature unit fixtures. | CTO + Domain Owner | Shopping aggregates two equivalent-looking strings or transfers an unsupported unit to Pantry. | Open |
| **R-06 Shopping repeats direct persistence from presentation.** `CookingHistoryNotifier` and `HeroSelectionNotifier` call `StorageService` directly (`cooking_history_provider.dart:3-12,76-81`; `recipe_provider.dart:96-145`). | High | High: feature logic becomes storage-coupled and transaction failures remain hard to test. | Accept repository-boundary ADR; add History/preference repositories and an import rule before Shopping begins. | Principal Engineer | A Shopping provider imports Hive or `StorageService`. | Open |
| **R-07 Optimistic Riverpod state survives a failed durable write.** Pantry and History notifiers change state before awaiting persistence (`pantry_provider.dart:124-194,219-253`; `cooking_history_provider.dart:17-25`). | Medium | High: UI displays changes that disappear on restart. | Return typed mutation results; commit state after durability or rollback deterministically; test repository failures. | Flutter Lead | Hive put throws, storage is unavailable, or serialization fails. | Open |
| **R-08 Completion undo becomes unavailable or duplicate.** Both `MainShell` (`main_shell.dart:35-62`) and `RecipeDetailPage` (`recipe_detail_page.dart:153-166`) clear/show completion snackbars after notifier-driven navigation. | High | Medium: user sees duplicate/transient feedback and loses the only quick recovery action. | Select one feedback owner, define navigation-safe undo lifetime, and add a completion-to-undo widget test. | Flutter Lead + UX | User finishes cooking and the route/tab changes while the snackbar is active. | Open |
| **R-09 Schema evolution silently drops or reinterprets local data.** One `Box<dynamic>` stores raw list/maps (`storage_service.dart:9-17,31-37,139-146`); malformed entries can be skipped (`106-136,171-199`). | Medium | Critical: Pantry or History data loss with no observable migration failure. | Version payloads, add deterministic migrations/backups and corrupt-data fixtures, and expose migration failures before adding Shopping storage. | Data/Persistence Owner | A field, ID, unit, or Shopping schema is introduced on an installed app with existing data. | Open |
| **R-10 CI gives date-dependent results.** The expiry test fixes July 2026 dates (`pantry_deduction_planner_test.dart:11-60`), while `Ingredient.isExpired` reads the wall clock (`ingredient.dart:70-91`). | High | High: release gate becomes red after a calendar boundary and expiry behavior is not deterministic. | Inject a clock/pass `now`; fix the test and run it with dates on both sides of expiry. | Test Owner | Test suite runs after 2026-07-25 or in a different timezone/date. | Open |
| **R-11 Critical workflow regressions escape unit coverage.** Coverage is 41%; `RecipeDetailPage` is 0.4%, `CookingHistoryPage` 0.9%, and `StorageService` 33%. | High | High: cross-provider failures ship while pure planners remain green. | Add application-service failure tests, Hive migration/restart tests, and targeted widget tests for complete/cancel/adjust/undo. | QA + Flutter Lead | Transaction orchestration is changed for Shopping or repository extraction. | Open |
| **R-12 Shopping starts from the wrong source baseline.** Current branch `d8631869` is 176 commits ahead of default `main` `b27e1762`, with active History/transaction files and no PR. | High | Critical: either current product code is omitted or an unreviewed base is inherited. | Review and reconcile the source branch; publish the approved base SHA before creating a Shopping feature branch. | CTO + Repository Maintainer | A Shopping branch is created before the current app branch is reviewed. | Open |
| **R-13 Performance degrades as Pantry, History, and Shopping grow.** Storage rewrites whole lists (`storage_service.dart:31-37,139-146`), broad providers watch all Pantry (`recipe_provider.dart:22-27,154-172`), and all tabs stay mounted (`main_shell.dart:65-76`). | Medium | Medium: slow writes, recommendation recomputation, and janky list updates. | Establish data-volume budgets, profile rebuild/write latency, introduce selective projections/paging only at measured thresholds. | Flutter Lead | P95 Pantry mutation or tab-render latency exceeds the agreed budget, or History grows beyond representative fixtures. | Open |
| **R-14 Offline presentation is not fully deterministic.** `AppTheme` uses `google_fonts` without disabling runtime fetching (`app_theme.dart:1-25`). | Medium | Low: first-run fallback typography or network attempts while offline. | Bundle fonts or disable runtime fetching; verify airplane-mode first launch. | Design System Owner | Fresh install launches without network or cached fonts. | Open |
| **R-15 Startup is blocked by local storage initialization failure.** `main` awaits `StorageService.init()` without a recovery path (`apps/mobile/lib/main.dart:7-12`). | Low | High: app cannot launch after box corruption, lock, or migration failure. | Add non-destructive startup recovery/error UI and test corrupt/locked store scenarios. | Persistence Owner | Hive open/migration throws before `runApp`. | Open |

## Current risk decision

The combined exposure of R-01, R-02, R-04, R-05, R-09, R-10, R-11, and R-12 makes Shopping Foundation **NOT READY**. None of these risks was accepted or closed by this documentation audit, and no production behavior was changed.
